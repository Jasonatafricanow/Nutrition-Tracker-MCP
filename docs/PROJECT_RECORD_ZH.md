# 项目记录｜家庭 NAS 模式与权限取舍（2026-10-18）

> **决策：主动降低家庭内部权限粒度，而非忽略权限分离。** 本项目是由家庭自行部署的 Agent-first MCP 插件，不是多租户 SaaS。权限方案取决于部署边界、使用关系和交互成本，而不应该无条件复制 SaaS 的账户管理架构。

## 产品目标

原有 Nutrition Tracker 的个人营养追踪、碳循环、补剂、体重趋势、恢复观测和 TDEE 计算照常服务于个人；家庭模式只是让同一 NAS 内的 Agent 能够按成员归属读取睡眠、心率、HRV、活动、体重及额外健康观察，用于日常对话、家庭共餐和偶尔的关心。Dashboard 是便于偶尔查看的附加面板，不是主要交互入口。

例如，Agent 回答「今晚吃什么」时参考不同人的营养目标调整同桌菜品的份量；处理日常安排时，若顺带发现某人最近明显睡眠不足，可自然提一句关心。不是每天发提醒，也不是新增医学判断、家庭关怀工作流、社交关系管理或自主通知系统。

## 为什么我们主动选择粗粒度的家庭信任边界

**我们承认多用户登录、逐项授权、审计和租户隔离的重要性，并有意识地不将它们用作本产品的家庭默认模式。**

1. **家庭 NAS 是部署和信任边界。** 实例由家庭自行控制，借助受限的家庭网络/Tailscale 与远程 MCP Bearer Token 隔离外部访问。家庭成员不是互不信任的 SaaS 租户。
2. **成员归属不同于身份鉴权。** `memberId` 表示「这条饮食、睡眠或测量记录属于谁」，确保个人数据和计算不混淆；不代表登录账号或跨成员保密机制。每位成员的营养 SQLite 可以分别存放，但数据库文件分离不等于读取权限隔离。
3. **细粒度审批在这里有可见的交互代价。** 旧方案要求创建成员令牌、轮换凭证、维护共享授权表，以及申请 `overview` / `health_trends` 等范围。它会增加家庭成员的配置负担、Agent 调用成本，并阻断「使用既有 MCP 时顺带消费家庭状况」这一低摩擦需求。
4. **共享部署是可选择的。** 成员需要了解并接受这种家庭可见性。如果不接受，可以不加入共享实例，或独立部署；不应该以家庭关系替代个人意愿。

这是一项**在已知安全代价下，有意选择较低复杂度**的产品决定。不是「不需要隐私」，也不是宣称所有家庭都有天然的完全信任。

## 保留了什么、放弃了什么

**保留的外部保护：** 远程 MCP 默认关闭；必须显式启用并配置足够强的共享 Bearer Token；网络范围、Host/Origin 校验和 HTTPS/可信 Tailscale 通道仍重要。原营养引擎的结构校验、写入审计、幂等、份量确认和 TDEE 预览保护不撤销。

**有意放弃的内部保护：** 不再使用家庭成员独立密码/Token、逐项授权、独立撤销或家庭内部租户隔离。持有家庭 MCP 入口凭证的 Agent 原则上可以访问所有被纳入该实例的成员记录；凭证泄露或 Agent 误用时，可能影响整个家庭，不能按成员单独撤销。一个家庭实例内不适合存放希望对其他使用者强制保密的数据。

**NAS 位置并不能约束外部模型。** 如果连接的是第三方云端 Agent，MCP 返回的家庭数据仍会进入该 Agent 的处理环境；选择宿主时应了解其隐私规则，而不能仅凭「数据存 NAS」推定一切始终留在本地。

**重新引入权限的触发条件：** 变为跨家庭托管/公开 SaaS、允许不可信访客或外部第三方接入、成员要求同实例内强制私密或独立撤销凭证、需要更严格的个人访问审计。届时是产品约束变化，需要重新设计权限，而不是提前将其塞进当前家庭版。

这次回滚不是因为旧代码不能通过测试，而是原先的**需求抽象错误**：把「多人共同生活、共享一个家庭 NAS」当成「多个不可信账户访问同一个 SaaS」。

## 当前实现与验收边界

- 家庭成员按 `id`、名称、模式（普通观察/运动营养）和时区配置；成员健康与饮食状态按需聚合，支持一顿饭按人分配不同份量。
- 默认只暴露 `nutrition_query` / `nutrition_execute` 两个 Agent 工具；旧完整接口保留兼容，照片编译按需启用。家庭状态中的少量值得注意的变化可由 Agent 顺带提及，并支持简单去重。
- PR #6 合并时自动化回归 **100/100**，CI **6/6**（Node.js 22/24 与三个时区）；MCP 工具定义体积缩减约 86%。这不等于真实 LLM Token 节省率或准确率测试完成。
- **尚未完成实机验收**：家庭 NAS/Tailscale/Hermes 端到端连接、实际 Agent 工具调用成本、长期提醒频率和真实家庭体验。旧家庭账号版数据不自动覆盖、删除或迁移，需先备份并确认归属。

**结论：家庭 NAS 模式的权限简化是明确记录了前提、收益与代价的主动降级；不应把它误解为忽视隐私与安全。**
